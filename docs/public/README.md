# 飞书数字分身

基于 Codex、飞书官方 CLI 和 lark-* Skills 的完整开源、自托管飞书数字分身。

它不是一个必须被 `@` 才工作的普通 Bot。新实例默认只处理 Bot 官方可见的实时消息；部署者一次性明确确认扩大 `message_scope` 后，才启用主体用户身份补充读取。Codex 根据自然语言规则决定忽略、回复、请求确认或调用飞书能力。

> 本项目不是飞书、Lark 或 OpenAI 官方产品。相关商标归各自权利人所有。

## 开源边界

项目不采用 Open Core。公开版本包含全部稳定功能、Codex 插件、伴随运行时、安装与诊断工具、配置 Schema、后台服务模板、测试和公共文档。

部署者自己的以下内容不会进入公共仓或发行包：

- OAuth、API Key、Token、Cookie、二维码和其他凭据；
- 真实用户、群、消息、Base、Wiki、Drive 等资源标识；
- 企业规则、知识空间映射、聊天和文档正文；
- SQLite、`*.privacy-key` 本机 HMAC 密钥、日志、缓存、备份和每日工作记忆；
- Codex 内部端点、模型选择和认证状态。

主体用户、控制 Base/表、明确配置的群级规则、知识空间和每日记忆目标等稳定资源标识可以保存在 Git 外 `0600` 的实例配置中；运行中临时发现的消息、话题、聊天和搜索结果标识只进入有保留期的本机运行态。两者都不得进入公共发行物。

## 核心能力

- 默认 Bot 实时事件，以及一次性范围确认后可启用的主体用户身份补充读取；
- 群聊、私聊、回复消息和话题消息的智能介入；
- 按需读取有界的同群历史，不建设长期聊天库；
- 收件来源固定回复身份，模型不能自行切换身份；
- 所有自动发言带明确的 `🤖` 标识；
- 通过官方飞书 CLI 使用消息、任务、日历、文档、Base、Drive 和 Wiki；
- 简单 Base 控制台、自然语言规则和群级特殊规则；
- 企业知识库辅助回复与每日工作记忆；
- 去重、补读游标、短期待确认、冻结和崩溃恢复；
- macOS 后台服务、状态检查、升级、回退和卸载。

## 架构原则

1. **AI 驱动**：业务判断和动作编排由 Codex 与 Skills 根据自然语言规则完成。
2. **官方组件优先**：飞书能力优先使用官方 `lark-cli` 和 lark-* Skills。
3. **最少自研代码**：只补事件接线、身份路由、去重、冻结、游标和短期状态等官方组件无法覆盖的缝隙。
4. **本机优先**：默认没有远程遥测，不上传调试包，不保存长期聊天正文。

```text
飞书 Bot 实时事件 +（范围确认后）主体用户身份补充读取
                         ↓
              伴随运行时 + 项目 Skills
                         ↓
                       Codex
                         ↓
              LarkGuard + 官方 lark-cli
```

项目不重建飞书 SDK、模型 SDK、动作目录、审批系统、工作流引擎或本地聊天数据库。

## Codex

运行时只调用 `codex exec --ephemeral`，不直接集成模型服务 HTTP API。部署者可以让 Codex 使用官方登录、API Key、自定义模型服务或企业网关；本项目不读取或解释这些内部配置。

项目只保存运行 Codex 所需的本机引用并执行无业务正文诊断，不提供 Provider 选择、切换、指纹、凭据存储或供应商专属适配器。模型凭据继续由 Codex 或部署者批准的秘密环境管理。

## 外部依赖与再分发

- Node.js、飞书官方 `lark-cli`、官方 lark-* Skills 和 Codex CLI 都是部署者单独安装、授权和升级的外部依赖，不随源码归档、Codex 插件或 npm 包再分发。
- npm 伴随运行时只使用 Node.js 内置模块，当前 `package.json` 没有 npm `dependencies`、`optionalDependencies` 或 `peerDependencies`。
- GitHub Actions CI 使用只读默认权限和完整 commit SHA，运行格式检查、公共快照策略、通用 Secret/PII 扫描、完整合成测试、真实 npm package lifecycle 测试和 npm 文件清单；REUSE、CodeQL、Dependency Review、Dependabot 与 Scorecard 已配置为在公共仓启用。正式候选已经生成确定性 SPDX 2.3、本地未签名来源记录并通过 REUSE 与只读消费者校验；公开发布时仍须在真实公共仓对最终产物生成 GitHub/Sigstore 签名 attestation。
- 项目不会把外部 CLI、Skills、登录态、Keychain 内容或模型配置复制进发行物。

## 配置与隐私

公开仓只提供中性配置示例。真实配置、凭据和运行状态必须保存在 Git 工作区之外的本机私有目录：目录权限为 `0700`，敏感文件权限为 `0600`。SQLite 同目录中的 `*.privacy-key` 保存本机标识投影所需的 HMAC 密钥，也必须使用 `0600`，不得复制到其他实例。

新实例的 `message_scope` 默认是 `bot_only`。`internal_visible` 只增加企业内部聊天补读；`all_visible` 还包括外部群。配置必须明确写出三档之一；首次使用非 `bot_only` 或扩大已有范围时，`setup` 要求显式传入 `--approve-message-scope`，否则在写入配置或启动服务前失败。Base 与 AI 都不能改变该范围。

公共高级 JSON 示例保持生产关闭、只启用消息域 `im`、无远程遥测，并默认只保留 7 天状态和 3 天日志。普通引导式完整安装强制使用 Base 控制台，因此本机能力域至少为 `im,base`，自动创建的总开关保持关闭。Schema 的不可突破上限仍分别是 30 天状态与 7 天日志，防止实例配置无限延长本机留存。

运行日志只允许记录版本、随机追踪号、阶段码、结果码、数量、耗时、脱敏错误分类，以及由本机隐私密钥生成、受保留期限制的类型化 HMAC `execution_hash`（仅用于重复执行审计）；不记录消息正文、模型输出、命令参数、`command_hash`、原始飞书 ID、凭据、Codex 配置或本机路径。`schedule.workdays` 可选使用 ISO 1–7 表示周一至周日，省略时默认周一至周五。

## 安装目标

稳定版本的用户路径只有三个主步骤：

1. [接入并授权飞书官方 CLI](../getting-started/feishu-cli.md)；
2. [启用一个允许处理相应数据的 Codex 环境](../getting-started/codex.md)；
3. [完成全局配置](../getting-started/global-configuration.md)，由安装器发现官方双身份并生成本机私有配置。

普通用户无需预写 JSON。引导安装默认使用 `message_scope=bot_only`、至少 `im,base` 域、7 天状态保留期和 3 天日志保留期；扩大消息范围必须再传 `--approve-message-scope`。Base 控制台及其“运行配置”“群级规则”两张表是完整安装的强制配置，但不要求提前手工创建。部署者可以传入已有 Base，或添加 `--create-missing-resources`，让 setup 使用官方 user 身份 CLI 完成精确名称发现、dry-run、Base/控制表/安全初始记录创建和读回。选择企业知识或每日记忆但没有稳定资源引用时，同一开关还会创建对应知识空间或日报目录。高级用户仍可使用 `setup --config ...`，但不能与自动创建开关混用。`setup` 已实现按需初始化、配置验证、Doctor、后台服务安装与启动、状态读回和最后解除冻结；重复执行会收敛，本机失败会恢复进入 setup 前的配置、冻结和服务状态，已创建的外部资源保留供安全重试。`status` 会返回 `degraded`、`safe-but-disabled` 或 `ready`，`control` 提供启用、冻结、升级、回退和卸载入口。

截至 2026 年 7 月 27 日，公共仓、完整运行时、Codex 插件、本机产品生命周期、控制 Base、知识空间、每日记忆、缺资源提示、官方 CLI 引导式创建、公共扫描、SBOM、来源记录和消费者一致性校验均已落地。目标长期运行实例已经完成配置化接管：版本切换后 `readiness=ready`，真实 Doctor、三个后台角色、服务连续性、单应用单消费者和冻结/恢复均通过；此前同一运行实现的双身份消息与每日工作记忆真人证据保持有效。本次只增加 setup 的薄编排，没有新增运行时业务代码。现有业务行为继续由 Codex、Skills 与自然语言配置驱动；控制台、知识空间和日报目录分别复用官方 Base、`wiki +space-create`、`drive +create-folder` 命令，可信代码不扩展为通用资源平台、工作流引擎或长期会话库。
