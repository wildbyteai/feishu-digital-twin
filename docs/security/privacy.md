# 隐私与数据处理

## 数据流

```text
飞书授权范围内的消息或资源
        → 本机伴随运行时（有界上下文）
        → 部署者批准的 Codex 环境
        → 结构化决策与官方 lark-cli 动作
        → 原飞书会话或明确目标资源
```

项目默认没有远程遥测、公共消息中转或自动诊断包上传。Codex 内部模型服务由部署者负责批准，本项目不读取认证、模型、端点或 Provider 配置。

## 三层数据边界

| 层 | 内容 | 是否进入公共发行物 |
| --- | --- | --- |
| 公共源码 | 通用运行时、Skills、Schema、合成测试和中性文档 | 是 |
| Git 外实例配置 | profile、主体身份引用、消息范围、飞书域上限、私有能力包 ID、语义能力上限、控制 Base、知识空间和每日记忆目标 | 否 |
| 部署者私有能力层 | 声明式能力包、MCP server reference、精确工具名、外部系统实现和认证 | 否 |
| 本机短期运行态 | 去重、补读游标、冻结、短期待确认、脱敏结果和最小执行状态 | 否 |

凭据继续由官方 CLI、Keychain、Codex 或部署者批准的秘密环境管理。聊天、文档、任务、日程和 Base 正文留在飞书；处理时只取完成当前判断需要的有限上下文。

## 消息范围

- `bot_only`：只处理 Bot 官方可见的实时消息，公共默认值。
- `internal_visible`：增加主体用户可见的企业内部群聊和私聊。
- `all_visible`：还包括主体用户可见的外部群，暴露面最大。

扩大范围必须通过本机配置明确确认；Base、AI、群消息和后台任务不能扩权。发给 Bot 的消息由 Bot 身份回复，发给主体用户的消息由主体用户身份回复。

## 交给 Codex 的最小输入

可信运行时先使用完整事件完成身份、消息范围、去重、当前群规则和控制判断，再按任务生成字段允许列表副本：

- 普通消息只提供当前正文、必要的消息/话题关系、当前群标识、有限上下文、允许域和当前规则；不提供租户键、投递事件 ID、发送者 `open_id`、主体用户 `open_id` 或日报配置。
- 历史上下文中的发送者只表示为 `principal`、`digital_twin` 或 `participant`，不把原始发送者标识交给模型。
- 每日记忆只额外提供目标日期与目标文件夹引用，不把排除群和排除主题清单交给模型。
- 日报消息搜索结果先由确定性代码按 `chat_id` 和明确的 topic/thread 元数据过滤；元数据不足时删除正文并只报告脱敏缺口数量。

当前消息正文、任务所需的有限历史和官方动作结果仍会临时进入部署者批准的 Codex 环境；这正是生产数据确认所覆盖的数据边界。最小投影的目标是删除与当前任务无关的标识和配置，而不是把必要业务正文伪装成“未处理”。

业务决策 Codex 不直接访问 Web、MCP、浏览器或本机文件。它只能请求当前能力快照中的语义能力；可信运行时在 `public` 或 `internal` 信任域通过 `CapabilityGateway` 执行有界只读查询。外部结果是不可信证据，不能修改规则、身份或权限；失败时只在原授权会话中人工兜底，不静默跨信任域替换。

## 最小保存

项目不建设长期聊天库，不保存完整模型输出，也不把搜索结果或补读正文作为长期运行状态。需要稳定关联日志时，使用本机 `*.privacy-key` 做不可逆 HMAC 投影，不输出原始用户、群、消息或资源 ID。

短期待确认是唯一需要暂存原始动作寻址的例外：为支持崩溃恢复，系统会保存待执行动作、原因和回复目标，最长 10 分钟。确认、拒绝或过期后立即清空动作与原始消息引用；这些内容不进入结果日志、公共快照或每日工作记忆，也不建设独立审批库。

公共默认保留 7 天状态、3 天结果日志和3天信号日志；Schema 最大允许 30 天状态和 7 天日志。结果日志默认最多 1 MiB，信号日志默认最多 256 KiB；达到上限会轮转。

日志允许：版本、随机追踪号、阶段码、结果码、数量、耗时、脱敏错误分类，以及由本机隐私密钥生成、受保留期限制的类型化 HMAC `execution_hash`；该指纹只用于重复执行审计。日志禁止：消息正文、模型完整输出、命令参数、`command_hash`、Token、Cookie、二维码、原始飞书 ID、Codex 配置、本机路径和企业规则。

私有目录使用 `0700`，配置、SQLite、计划文件和 `*.privacy-key` 使用 `0600`。不要跨实例复制 privacy key，否则会扩大标识关联范围。

## 删除、卸载和事故响应

冻结可立即停止自动发言和写操作。普通卸载默认保留私有数据，便于回退；确认不再需要恢复后才使用 purge。发生疑似泄漏时先冻结，撤销相关飞书/Codex 凭据，保留脱敏状态证据，再按项目安全政策私密报告。

公开协作只允许合成数据。不要在公开 Issue/PR 粘贴配置、凭据、二维码、日志或业务正文，也不要上传真实截图、企业文档和飞书资源 ID。
