# 飞书 Base 控制台

控制台只用两张表，由官方 `lark-base` Skill 和 lark-cli 创建、编辑和读取。

## 运行配置

运行配置表只保留一条记录；日常只操作一个总开关。

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| 名称 | 文本 | 配置名称 |
| 数字分身启用 | 复选框 | 唯一运行开关；关闭时不代表主体用户发言或执行动作 |
| 允许域 | 多选 | 在本机权限上限内进一步收紧可调用的 lark-cli 域，不能扩权 |
| 个性化规则 | 多行文本 | 交给 AI 的自然语言职责、风格和授权规则 |

## 群级规则

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| 群名称 | 文本 | 便于人识别 |
| 群ID | 文本 | `oc_` 开头的真实 chat_id |
| 启用 | 复选框 | 是否启用该群的特殊规则 |
| 个性化规则 | 多行文本 | 该群特有的职责、语气、承诺或信息边界 |

## 接入配置

已有 Base 可通过普通 setup 引用：

```bash
feishu-digital-twin setup \
  --capabilities message,console \
  --console-base-token <base-token> \
  --console-runtime-table <运行配置表名或ID> \
  --console-group-rules-table <群级规则表名或ID> \
  <其他必需的 setup 选项>
```

三个 `--console-*` 选项必须同时提供。setup 自动补齐 `base` 业务域，通过官方 `base +record-list` 只读两张表并确认运行行和表结构可用；它不写入、创建或改造 Base，并将控制模式设为 `base`。选择 Base 后，不允许再用本机 `authority_rules` 或 `group_rules`；知识空间路由也应写入 Base“个性化规则”，避免两个规则源。

高级配置文件中的对应结构为：

```json
{
  "control": {
    "mode": "base"
  },
  "console": {
    "base_token": "replace_me",
    "runtime_table": "运行配置",
    "group_rules_table": "群级规则"
  }
}
```

运行时通过官方 `base +record-list` 读取两张表，不维护本地配置编译器。群的内外部属性由官方 IM 群资料提供，不需要人工维护准入名单。Guard 会阻止 AI 动作命中这个控制 Base，避免数字分身自行改变运行开关或授权规则。

本机配置中的 `allowed_lark_domains` 是不可突破的权限上限。运行表必须包含“允许域”字段，且值严格为“继承”时才使用本机上限；有效非空列表必须全部属于本机上限，并按该列表收紧权限。字段缺失、显式空值、空数组、空白、混合“继承”、未知域或任何超出本机上限的值都导致配置快照加载失败关闭，不能被解释为继承、忽略或扩权。

`control.mode=base` 时，Base 是个性化规则和群级规则的唯一来源。“个性化规则”为空就表示当前使用空规则，不回退或继承本机规则，也不与本机规则自动拼接。群级规则以 Base 表中当前启用的记录为准。自然语言规则可以改变授权域内的业务处理方式，但不能改变 `message_scope`、扩大 `allowed_lark_domains`，也不能绕过身份路由、AI 标识、冻结、所有权转让禁令和官方确认等可信硬门。

“数字分身启用”、允许域、个性化规则、群级规则和其中的知识空间路由共用 10 秒短缓存，最长约 10 秒后会在下一条新消息处理前一起刷新。同一条消息从判断到执行固定使用同一个配置快照，避免处理中途规则或权限改变。关闭总开关后不调用 AI、不代表主体用户发言，也不执行动作。`production_data_approved` 只是部署时一次性确认模型服务的数据处理范围，不是日常控制门。后台保留故障急停，但不进入控制台；平时只使用“数字分身启用”。

## 企业知识库路由

知识库路由继续复用“个性化规则”，不新增表或字段。规则记录知识空间名称、`space_id` 和适用方向；AI 根据聊天主题选择最多两个空间，用官方 Drive 搜索候选；Wiki 链接先解出底层对象类型，再按类型读取正文或结构化数据。

示例路由方向：

- 产品规格、产品任务与版本计划 → 产品知识空间；
- 项目交付、系统运维与故障处理 → 项目知识空间；
- 财务、人力、渠道与组织制度 → 企业制度知识空间；
- 无法确认接收者权限的空间不进入当前回复。

知识空间 ID 的权威值保存在 Base 个性化规则中，避免在运行时代码中硬编码。空间重建或 ID 变化时只需更新该规则，不需要发布代码。
