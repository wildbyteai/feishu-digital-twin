# 完整能力公开，不采用 Open Core

飞书数字分身的公开目标是一个可真实安装、授权、后台运行、升级、回退和卸载的完整产品，而不是仅供阅读的公共核心、功能缩水的社区版或长期停留在源码预览状态的样例。

公共版本必须包含当前稳定数字分身的完整能力：Bot 实时事件、主体用户身份补读、AI 智能介入、有界上下文、固定身份回复、`🤖` 标识、官方飞书能力编排、Base 控制台、企业知识库辅助、每日工作记忆、最小状态、去重、冻结、短期待确认、后台连续运行和故障恢复。部署者可以按需关闭能力，但公开代码不得因版本分层而扣留这些能力。

公开产品采用同一仓库、同一版本的三层结构：Codex 插件负责 Skills、安装和控制体验；伴随运行时负责官方组件无法承担的常驻接线与可信边界；用户本机私有层只保存凭据、真实资源标识、个性化规则、运行状态和业务数据。私有层不得包含仅对当前维护者开放的功能实现。

实施和验证可以使用不同成熟度标识，但不形成永久功能分层。普通安装通过受保护的公共主干交付，用户可以交给 Agent 安装，或使用无标签的 `npx` 命令运行；只有需要锁定精确源码或执行显式升级、回退时才使用不可变 Git 标签，稳定主干合并本身不强制创建标签。Codex 插件包与 npm tarball 只作为本地一致性和安装闭环验证产物；当前不创建 GitHub Release，也不发布 Codex Marketplace 或 npm registry。若以后增加其他分发渠道，必须另立架构决策并重新完成供应链验收。

首个完整版本可以只声明 macOS 为受支持平台；这是运行环境支持范围，不是功能缩水。Linux、Windows 和多实例属于后续可移植性工作，不得为此引入共享多租户 SaaS、重建飞书 SDK、动作目录、工作流引擎或长期聊天库。

所有飞书业务能力继续优先使用官方 `lark-cli` 与 lark-* Skills。`lark-channel-bridge` 只作为安装和服务体验参考，不进入依赖树；只有第一方 Channel SDK 经隔离验证能够减少维护代码且不改变上层行为时，才可替换 Bot 事件适配器。
